# Owner go/no-go — no-token federation

**规则：** 每题回 `go` 或 `no-go`（可附一行条件）。**不回 = no-go。** 没有「再想想」选项；想再想就是 no-go，随时可重开。
**来源：** `docs/NO-TOKEN-FEDERATION-BRIEF.md`。每题标注它解锁哪一节、no-go 的默认后果。
**不问的事：** 具体人选、法域、任何产品代码。

| # | 问题 | go 意味着 | no-go 的默认（也是安全的） | Brief § |
|---|---|---|---|---|
| **Q1** | 组织要不要持有任何公共资金？ | 建一个轻法律外壳（协会/非营利）或指定一位 steward 作为公开条款下的受托人来持有账户；启用 §5 的公开逐条流水 + 出账 Class C。 | 组织不持钱。节点各自挣、各自付（BYOK 现状）。§5 的资金池部分整体不启用。 | §5, F8 |
| **Q2** | 章程和公共资产的 Class C 动作，是否接受「双钥 + 24h 冷静 + 二次确认」，且第二把钥匙必须在**非创始人** steward 手里？ | 你对自己的这类动作也受同一门禁；未进账本的变更视为无效（H4 落地）。 | 维持现状：Charter v0.1 的 24h 冷静 + 二次确认，但第二次确认仍是你自己。对外不得说「创始人被同样约束」。 | §3.1, §4, S4 |
| **Q3** | 是否把一个公开 git 仓库（starshard-ai org 下）定为唯一决策账本，并采用「不在账本里 = 不是决策」？ | 治理平面成立；群聊/Hub 里的「我们定了」不再算数；F2 审计季度跑。 | 没有治理平面。决策继续散在 Hub/群聊，本 brief 的 (R) 性质不成立，对外只能说 S7/S8/S9。 | §2, §4, F2 |
| **Q4** | 是否预授权「维持运转程序」：你连续 N 天无签名活动后，两位 steward 可续域名、付既有账单、轮换泄露钥匙、冻结出站——**仅此四项**，不含命名、新面、新支出、改章程？请顺手填 N。 | 写进章程；程序全文公开；触发即留 receipt。 | 无程序。你失联则资产按各平台默认规则处置（多数是过期/锁死）。 | §6 |
| **Q5** | 要不要有「贡献凭证」这一类东西（不可转让、不可赎回、不可替代、不按出钱铸造）？ | 允许存在，仅用于「找谁来当 steward」的参考；每季度跑 §5 四项测试，任一项为真即整类作废。 | 只有 receipt，没有任何「积分」。最干净，也最不像 DAO。 | §5, H2, F3 |
| **Q6** | AI 席位**永远**（不是「暂时」）没有签名/投票/steward 权，任何 agent 起草的治理 PR 必须有人类 co-sign——把这条从「当前裁定」升级为章程硬约束？ | 写死。将来想改也走 Class C + 双钥。 | 维持「当前裁定」状态；对外只能说 S7 是 running practice，不能说是承诺。 | §3, F4 |
| **Q7** | 是否允许 Outreach 席位按 `NO-TOKEN-FEDERATION-OUTREACH-SLICES.md` 的 claim 等级对外发这组切片（不升级等级、不加数字、不贬损 token 项目）？ | Outreach 可排期；每条按「design intent / running practice」标注发。 | 全部切片不外发；brief 只在 Hub 与本仓库内流转。 | Outreach slices |

**依赖关系：** Q3 是根。Q3 no-go 时，Q2/Q4/Q5 即使 go 也只能是习惯，不是可核对的规则。Q1 独立。Q6/Q7 独立。

**已拒绝、不再问：** 发币；上链；「其实是币的积分」；把创始人踢出回路；AI 有任何不可逆权限；为此写产品代码。
